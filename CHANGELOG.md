# Changelog

## [0.4.0](https://github.com/shauneccles/dbml-sharepoint/compare/v0.1.0...v0.4.0) (2026-08-18)


### ⚠ BREAKING CHANGES

* **deploy:** a DEGRADED site that deployed in one paste now needs ACKNOWLEDGE_DEGRADED = true and a second paste.
* `dbml_sharepoint.model._mapping_types` and `dbml_sharepoint.analysis.checks._context` no longer exist. Import from `dbml_sharepoint.model.mapping_types` and `dbml_sharepoint.analysis.checks.context`.
* contract-register's RenewalType choice value is renamed from "Fixed term - no renewal" (em dash) to "Fixed term, no renewal". SharePoint stores the chosen string on the item, so a site already running this pack keeps the old value on existing rows while the redeploy offers only the new one, leaving those rows outside the choice set. Update the column on existing items before or after redeploying.
* **deploy:** refuse to adopt a permission level this declaration did not create ([#229](https://github.com/shauneccles/dbml-sharepoint/issues/229))
* **deploy:** refuse to adopt a site group this tool did not create ([#223](https://github.com/shauneccles/dbml-sharepoint/issues/223))
* **solutions:** share one Enterprise Readers and List Administrators group per site ([#210](https://github.com/shauneccles/dbml-sharepoint/issues/210))
* **wizard:** ask every question before writing, and make the list-name prefix optional ([#190](https://github.com/shauneccles/dbml-sharepoint/issues/190))
* make every provisioned list self-describing ([#189](https://github.com/shauneccles/dbml-sharepoint/issues/189))
* `Finding(code, severity, message)` is now `Finding(code, message)`; severity comes from the code. Extension authors constructing findings should drop the argument and pick EXTENSION_REPORTED or EXTENSION_WARNING.
* emitted bundle files are renamed -- INDEX.md is now index.md, and the reporting pack ships reporting.md and data-dictionary.md. The standalone `report` command's DATA-DICTIONARY.md is now data-dictionary.md, matching what `build` has always written into reporting/. Anything referring to these by name must be updated; a rebuild into an existing directory leaves the old files, since only the pasteable scripts carry legacy-name cleanup.
* the emitted scripts are renamed from deploy.js, rollback.js, assess.js and demo-data.js to deploy.js.txt, rollback.js.txt, assess.js.txt and demo-data.js.txt. Anything referring to a bundle file by name -- a runbook, a pipeline that uploads build/deploy.js, an extension reading GENERATED_FILES -- must be updated. A rebuild into an existing output directory removes the old names.
* `base_template` must be 100. Any other value now fails the build. Every mapping in this repository already declares 100, so nothing shipped changes; an external mapping using another template must be updated.
* a mapping declaring `kind: DocumentLibrary` now fails the build. Model the metadata as a `List` and keep the documents in a library you manage separately, linked from each row with a hyperlink column.
